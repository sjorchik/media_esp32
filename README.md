# Медіамодуль WROOM (ESP32-WROOM-32, без PSRAM)

Прошивка `FW_VERSION = 0.3.0`, `proto_ver = 2`. Контракт із головним S3: [docs/UART_CONTRACT.md](docs/UART_CONTRACT.md).

## 1. Призначення

Медіамодуль до ESP32-S3. Приймає команди від S3 по UART1 (921600 8N1), відтворює звук з одного активного джерела і шле стан та події назад.

- **BT**: A2DP-приймач з AVRCP. Працює.
- **SD**: MP3 з картки (SdFat, hot-plug, плейлист, shuffle, резюме).
- **USB**: через CH376S. Поки заглушка (`ENABLE_USB_CH376 = 0`, у `MEDIA` завжди `usb=0`).

Звук виводиться по I2S на ЦАП. Гучністю, тембром і входом керує лише S3 (TDA7318); цифровий EQ і послаблення виходу S3 задає командами `EQ` і `LVL` (M6b). WROOM мʼютить свій ЦАП сам.

## 3. Збірка, прошивка, тести

Середовища (`platformio.ini`):

- `esp32dev` — **реліз** (за замовчуванням). `BOOT_TEST_CMDS=0`, `SKIP_TEST_CMDS=0`.
- `esp32dev_test` — стенд. Успадковує `esp32dev` і додає `-DBOOT_TEST_CMDS=1 -DSKIP_TEST_CMDS=1`. Не для релізу.
- `native` — юніт-тести (`pio test -e native`). Збирає `proto/frame`, `proto/cmd_args`, `media/id3`, `media/shuffle`, `storage/resume_record`, `storage/settings_record`, `storage/boot_guard`.

Команди (COM-порт підставити свій):

```
pio run -e esp32dev
pio run -e esp32dev -t upload --upload-port COMx
pio device monitor -p COMx -b 460800
pio run -e esp32dev_test
pio test -e native
```

Прапорці збірки (типові значення з `src/config.h`, якщо не задано в `platformio.ini`):

| Прапорець | Типово | Призначення |
|---|---|---|
| `DAC_MUTE_ACTIVE_HIGH` | 0 (у `esp32dev` задано 1) | 0 = PCM5102 (XSMT: HIGH = звук); 1 = UDA1334A (MUTE: HIGH = мʼют) |
| `HAVE_DAC` | 1 | Лише для логу: 0 → «DAC відсутній» |
| `LOG_LEVEL` | 3 | 1=E 2=W 3=I 4=D |
| `AUTO_RESUME_SOURCE` | 0 | 1: після старту вмикати останнє джерело |
| `ENABLE_USB_CH376` | 0 | 1: драйвер CH376S (етап 4) |
| `SD_CD_ACTIVE_LOW` | 1 | Полярність card-detect |
| `BOOT_TEST_CMDS` | 0 | 1: `DBG,boot,crash`, `DBG,boot,set,<n>` |
| `SKIP_TEST_CMDS` | 0 | 1: `DBG,failnext`, `DBG,media,ins\|rem` |
| `ALWAYS_MUTE_ON_TRACK_START` | 1 | Мʼют на старті кожного треку (обхід M3c) |

## 4. Архітектура

### Задачі

| Задача | Ядро | Пріоритет | Стек | Роль |
|---|---|---|---|---|
| BTC_TASK, BTU_TASK, BtAppT | 0 | SDK | SDK | BT-стек (створює бібліотека A2DP) |
| link_tx | 0 | 3 | 4096 | Передача кадрів на S3 |
| link_rx | 0 | 3 | 4096 | Прийом кадрів із S3 |
| console | 0 | 2 | 4096 | UART0: DBG-команди, лог |
| audio | 1 | 6 | 4096 | Помпа PCM з BT-кільця в `AudioOut`, тест-тон |
| mp3 | 1 | 5 | 20480 | Декодер minimp3; стек статичний, у `PcmArena` |
| app (loopTask) | 1 | 1 | — | Усі команди, `SourceManager::loop`, `BtSource::service`, скан SD, запис NVS |

Команди з UART0 і UART1 не виконуються у своїх задачах. Роутер лише валідує і кладе `Cmd` у чергу (глибина 16), виконує `app`. Так немає гонок за станом. BT-колбеки лише кладуть події в Inbox під spinlock.

SdFat не потокобезпечний: усі виклики серіалізує мʼютекс у `sd_media.cpp`. Присутність картки під час відтворення визначається по `SD_CD_PIN`, без SPI.

### Потік даних

- **SD:** файл → mp3 (читання 6144 Б, докачування при < 3072 Б) → `AudioOut::write()` → I2S DMA (8 буферів × 128 кадрів ≈ 23 мс).
- **BT:** A2DP PCM → кільце 16384 Б (≈ 93 мс) → задача `audio` (порції по 1024 Б) → `AudioOut`. Передзапуск 4096 Б після старту або underrun.
- **Лінк:** TX високого пріоритету (8 слотів: STATE, ERR, READY, MEDIA, BT), TX низького (12 слотів: TRACK, FOLDER, META), TIME — окремий слот.

### Мʼют і джерела

- `AudioOut::earlyMute()` — перший рядок `setup()`: DAC у мʼюті до будь-чого іншого.
- DAC мʼютиться при `state != play` і при `src=off`. Перед зупинкою мʼют, без клацань.
- Активне лише одне джерело. `SRC` зупиняє попереднє, мʼютить DAC і вмикає нове.
- BT підʼєднаний (connectable, реконект) лише при `src=bt`. В інших станах розрив і non-connectable/non-discoverable.

## 5. UART-контракт

Кадр: `$BODY*XX\n`, XOR-сума двома hex-цифрами, LF. Максимум 255 Б. Повний опис, команди, події, семантика і приклади: [docs/UART_CONTRACT.md](docs/UART_CONTRACT.md). Будь-яка зміна контракту — нова `proto_ver` і одночасне оновлення обох сторін.

**proto_ver = 2 (M6b).** Історія: v1 → v2 — додано `EQ` і `LVL`. Константа `kProtoVer` лише в `src/config.h`.

- Після `HELLO,2`: `READY` і повний стан, далі S3 шле `SHUF`, `REP`, потім `EQ` і три `LVL`. `HELLO` з іншою версією (зокрема `HELLO,1`) — лише `READY` (у ньому proto = 2), без стану й `ERR`.
- `EQ,<g1>,<g2>,<g3>,<g4>,<g5>` — смуги 60/250/1000/4000/12000 Гц, цілі дБ −12…12, рівно 5 аргументів, діє на всі джерела.
- `LVL,<bt|sd|usb>,<дБ>` — цифрове послаблення виходу слота, ціле −40…0; діє, коли це джерело активне.
- Обидві приймаються в будь-якому `state` і при `src=off`, без підтверджень і подій; у `STATE`/`GET` нічого не додається. Некоректні → `ERR,bad_arg,<EQ|LVL>`, нічого не застосовується (для `EQ` або всі 5, або жодного).
- Значення лише в RAM (NVS не пишемо): після перезавантаження 0 дБ, поки S3 не надішле їх знову.
- Виконує роутер у задачі `link_rx`/`console` (без черги до `app`): `eq::setAllDb` і `level::setDb` атомарні, як і в `DBG,eq`/`DBG,lvl`. Консоль UART0 приймає ті самі рядки: `EQ,3,0,0,0,3`, `LVL,sd,-20`; застосоване показують `DBG,eq` і `DBG,lvl`.

## 6. Можливості й ліміти

- **Формати:** лише `.mp3` (регістр не важливий). Приховані файли й імена з крапки ігноруються.
- **Глибина:** 3 рівні (корінь = 0). Порядок — порядок каталогу FAT.
- **Ємність плейлиста:** контракт вимагає ≥ 300 треків. Арена 16384 Б (`kPlaylistArenaBytes`), реальна ємність залежить від довжини імен. Виміряно: 121 трек, 4137 Б із 16384 Б. Для ≥ 300 треків — TBD (вимір). Надлишок → `ERR,too_many_files`.
- **Навігація:** NEXT/PREV циклічні. PREV: позиція > 3 с → перезапуск треку (`kPrevRestartMs`). FNEXT/FPREV — перший трек сусідньої папки.
- **Повтор:** REP 0 — далі, після останнього stop. REP 1 — повтор треку. REP 2 — цикл усього списку.
- **Shuffle:** Fisher-Yates по всіх треках, без повторів до кінця кола. Перестановка 2 Б на трек. Історія 32 треки (`kHistLen`). Для BT не впливає на відтворення.
- **Помилки відтворення:** `read_fail`/`decode_fail` → `ERR` і пропуск. Після 3 підряд (`kPlayErrStop`) → stop. Лічильник скидається після 1 с відтворення (`kPlayOkMs`).
- **Резюме:** окремо для SD і USB: шлях + зсув, блоби `rsm_sd` / `rsm_usb`. Запис раз на 10 с (`kResumeSaveMs`), лише якщо зсув змінився ≥ 128 Б. Зсув ближче 4096 Б до кінця ігнорується.
- **NVS**, простір `media`:
  - `rsm_sd`, `rsm_usb` — резюме треку.
  - `set_v1` — налаштування (`last_src`, `shuf`, `rep`), блоб 10 Б з CRC32.
  - `boot_crash` — u8, лічильник аварійних перезапусків.
  - `last_src` — застарілий u8 попередньої версії. Стирається одноразово при старті (M5c6), запису не робиться.
- **Захист від петлі аварій:** 3 аварійні перезапуски підряд (`kCrashLoopMax`) → режим захисту на цей запуск. Лічильник скидається після 60 с стабільної роботи (`kBootStableMs`).
- **ID3:** v2 (Latin1, UTF-16, UTF-8), до 48 кадрів, до 32 КБ читання. Кирилиця в cp1251 розпізнається евристично (`kId3Cp1251Pct = 50`). Вихід завжди UTF-8.
- **Hot-plug SD:** антидребезг 100 мс, повтор mount 3000 мс, відкат частоти SPI 20 → 10 → 4 МГц при помилках.

## 8. Скрипти `tools/`

Усі скрипти потребують `pyserial` (`pip install pyserial`). Адаптер USB-UART 3,3 В: TX → GPIO32, RX ← GPIO33, спільна земля. S3 має бути відʼєднаний від GPIO32/33.

- `tools/m5c1_series.py COMx [серій=20] [read|decode]` — серія `DBG,failnext,1` + `NEXT` через UART0. **Потребує `esp32dev_test`.** Лог: `m5c1_series.log`.
- `tools/m5c4_frames.py COMx [--only a,b] [--list] [--usb-expected 0|1] [--expect-title назва] [--max-next 5]` — перевірка протоколу UART1 (proto_ver = 2, зокрема сценарії `eq_lvl`, `eq_lvl_bad`): PASS/FAIL/SKIP/INFO. Код виходу: 0 — без FAIL, 1 — є FAIL, 2 — порт або передумова.
- `tools/m5c5_src_stress.py --ctl COMx --dbg COMy [--cycles 100] [--seed 1] [--settle 15] [--no-usb] [--no-bt] [--warmup 2]` — стрес SRC (UART1 + UART0). Код виходу: 0 — без FAIL.
- `tools/m5c5_src_stress.py --dbg COMy --burst 50` (і `--burst 200`) — пачка рядків у UART0, без `--ctl`. Код виходу 1, якщо є втрати.

Примітка: `m5c5` вимикає DTR/RTS до відкриття UART0, бо відкриття скидає плату.

## 9. Ресурси

Вимір M5c5: `esp32dev`, `SKIP_TEST_CMDS=1`, `ALWAYS_MUTE_ON_TRACK_START=1`, `CONSOLE_RX_BUF=1472`. Цифри релізної збірки (M5c6, `SKIP_TEST_CMDS=0`) — TBD (вимір).

- **Розмір збірки:** RAM 32,8 % (107336 з 327680 Б). Flash 31,4 % (1256277 з 3997696 Б).
- **Heap, free / largest / min_free, Б:**
  - `src=off` після завантаження: 27640 / 24564 / 24512.
  - SD-play (121 трек): 27640 / 24564 / 24512.
  - BT підключено, play: 17832 / 16372 / 10448.
  - BT → off після розриву: 23988 / 16372 / 10448.
- **Запас стеків (мін. вільно), Б:** app 5608, link_tx 2096, link_rx 3400, console 1936, audio 3352, BTC_TASK 6628, BTU_TASK 6376, BtAppT 2144, mp3 3004 із 20480 (після першого play; до нього 19932).
- **Декодер (SD, 44100 Гц, 2 канали, 320 кбіт/с):** навантаження середнє 11,6 %, максимум 14,3 %. Час кадру середній 3052 мкс, максимум 3736 мкс (тривалість кадру 26122 мкс). 531 кадр, пропущено 0, ресинхронізацій 0, underrun 0, write_timeout 0.
- **SD:** читання 813 КБ/с (максимальний виклик 4831 мкс). Скан 121 трек, 1 папка, 1024 мс (робота 610 мс), арена 4137/16384 Б. Розбір тегів ≈ 2 мс.
- **Буфери:** вхід 6144 Б, PCM-кадр 4608 Б, область PCM 38400 Б, DMA 1024 кадри (≈ 23 мс).
- **BT (SBC, 44100 Гц):** PCM 176640 Б/с. За ≈ 5 МБ — underrun 2, max_write 5885 мкс, кільце 5632/16384.
- **AudioOut:** мʼют/анмʼют парні. `waitUnmuted` довше 3000 мс: 0 разів.

## 10. Відомі обмеження і рішення

- **Q3:** порядок Hi/Lo у `Link`.
- **Q4:** додатковий TIME.
- **Q5:** STOP/PAUSE у стані scan дають `bad_state`.
- **Q6:** переповнення черги команд — лише лог.
- **Q10:** порожнє імʼя команди.
- **USB:** заглушка до етапу 4. Відповідає `MEDIA,<sd>,0`.
- **Консоль UART0:** пачка без втрат до ≈ TBD (вимір, `--burst 200`). Буфер 1472 Б. Відповідь `DBG,*` блокує консоль на TX (≈ 1,4 мс на рядок).
- Деталі Q3–Q10 не входять до дампів; тут наведено формулювання з переліку обмежень.

## 11. Усунення несправностей

- **Немає звуку або постійний мʼют.** Перевірити `DAC_MUTE_ACTIVE_HIGH` проти реального ЦАП: невідповідність тримає мʼют. `DBG,aout` (мʼют, лічильники). `DBG,tone` при `src=off`.
- **SD не монтується.** Перевірити картку (FAT) і card-detect (пін 21, LOW = вставлено). `DBG,sd`, `DBG,media`. Hot-plug без перезавантаження: `DBG,media,rem`, далі авто-mount (лише `esp32dev_test`).
- **BT не підключається.** `DBG,bt`. Вікно сполучення `DBG,bt,pair` (120 с). Старий звʼязок — `DBG,bt,forget`.
- **Плата перезавантажується при відкритті UART0.** Відкриття порту може скинути ESP32 через DTR/RTS. Це очікувано, не помилка.
- **Помилка «модуль недоступний» на S3.** Немає валідного кадру 3 с. Перевірити лінію GPIO32/33 і рівні 3,3 В. Перевірити `DBG,link`.
- **Незнайомий ключ NVS у логах.** Після оновлення перший запуск пише `застарілий ключ last_src стерто`. Далі рядка немає.
