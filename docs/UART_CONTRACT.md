# UART-контракт S3 ↔ WROOM (proto_ver = 1) — змінювати заборонено

```
=== UART-КОНТРАКТ S3 ↔ WROOM, proto_ver = 1 ===

1. ФІЗИЧНИЙ РІВЕНЬ
UART 921600, 8N1, без flow control, рівні 3,3 В, спільна земля.
S3 (UART1): TX=GPIO42 -> RX WROOM (GPIO32); RX=GPIO48 <- TX WROOM (GPIO33).

2. КАДР
$<BODY>*<XX>\n
- BODY = NAME[,арг1,арг2,...]; XX = XOR усіх байтів BODY, 2 великі hex-цифри.
- Кінець кадру: LF; CR ігнорувати. Максимум 255 байтів на кадр разом зі службовими.
- Текст у UTF-8. У текстових полях екранувати відсотковим кодуванням: % -> %25, "," -> %2C, * -> %2A, $ -> %24, будь-який байт < 0x20 -> %XX (зокрема %0D, %0A). Решта байтів (кирилиця) передається як є.
- Порожнє поле допустиме. Числа десяткові, булеві 0/1, час у цілих секундах.
- Приймач мовчки відкидає кадр із поганою сумою, завеликий або без $. Символ $ усередині розбору перезапускає розбір (ресинхронізація). Невідому команду: відповісти ERR,unknown_cmd,<NAME>.
- Відправник сам скорочує текстові поля (по межі UTF-8-символу), щоб закодований кадр вміщався в 255 байтів.
Приклади (мають бути в unit-тестах обох сторін):
$HB,1*17     $PLAY*04     $SRC,sd*79     $STATE,sd,play,0,0*44

3. HEARTBEAT І СТАРТ
- Обидві сторони шлють HB,<seq> кожні 1000 мс (seq 0..65535 по колу).
- Немає жодного валідного кадру 3000 мс -> сторона вважає партнера недоступним (S3 показує «модуль недоступний»; WROOM лише логує, відтворення не змінює).
- WROOM після завантаження шле READY,<fw_version>,<proto_ver>. Початковий стан: src=off, state=idle, DAC замʼючений.
- S3 після власного старту і щоразу, коли WROOM знову стає доступним, шле HELLO,<proto_ver>. WROOM відповідає READY і повним станом (як на GET). Далі S3 шле збережені SHUF і REP.
- Якщо proto_ver не збігається, S3 показує помилку версії і не керує модулем.

4. КОМАНДИ S3 -> WROOM (підтверджень немає, результат приходить подією STATE/іншою)
HELLO,<ver> | GET (повний стан: STATE, MEDIA, BT, а при активному джерелі ще TRACK, FOLDER, META, TIME)
SRC,<bt|sd|usb|off> | PLAY | PAUSE | TOGGLE | STOP
NEXT | PREV | FNEXT | FPREV | SHUF,<0|1> | REP,<0|1|2>
Зарезервовано, у v1 не реалізується (відповідь ERR,not_implemented): LIST,<offset>,<count> та PLAYFILE,<index>.

5. ПОДІЇ WROOM -> S3
READY,<fw>,<proto>
STATE,<src>,<state>,<shuf>,<rep> : src=bt|sd|usb|off; state=idle|scan|play|pause|stop; шлеться при кожній зміні
MEDIA,<sd>,<usb> : 1 якщо носій змонтовано, 0 якщо ні; при зміні і на GET
BT,<connected|disconnected>,<імʼя пристрою>
META,<виконавець>,<назва>,<альбом> : при зміні треку одразу з тим, що відомо (назва за замовчуванням = імʼя файлу без розширення), потім повторно після розбору тегів
TRACK,<номер з 1>,<всього> : лише sd/usb
FOLDER,<назва папки>,<треків у папці> : лише sd/usb
TIME,<поз_с>,<трив_с> : раз на 1000 мс під час play і один раз при pause; трив=0, якщо невідома
ERR,<код>[,<деталь>] : unknown_cmd, bad_arg, bad_state, no_media, read_fail, decode_fail, too_many_files, not_implemented, bt_fail
Рекомендований порядок при зміні треку: TRACK, FOLDER, META, TIME, STATE.

6. СЕМАНТИКА
Джерела:
- Активне лише одне. SRC зупиняє попереднє, мʼютить DAC і вмикає нове. SRC,off: зупинка, мʼют (XSMT), вхідний A2DP-звук відкидається, телефону шлеться AVRCP pause.
- sd/usb: якщо носія немає -> STATE,<src>,idle + ERR,no_media. Інакше state=scan, потім автоматично продовжується збережений трек з позиції (резюме, див. нижче).
- bt: idle = пристрій не підключено; stop = підключено, не передає; play/pause = за статусом AVRCP.
- У стані scan команди NEXT/PREV/FNEXT/FPREV/PLAY ігноруються з ERR,bad_state.
Навігація (sd/usb):
- Підтримуються лише .mp3 (регістр байдужий), приховані файли й імена з "." на початку ігнорувати. Порядок: порядок каталогу FAT, підпапки в глибину, до рівня 3. Мінімум 300 треків; надлишок ігнорувати з одним ERR,too_many_files; реальний ліміт реалізація документує.
- NEXT/PREV завжди циклічні (з останнього на перший і навпаки).
- PREV: якщо позиція > 3 с, перезапуск поточного треку, інакше попередній (у shuffle по історії).
- FNEXT/FPREV: перший трек наступної/попередньої папки (за порядком каталогу, циклічно). У shuffle це ручний стрибок: трек потрапляє в історію, далі порядок продовжується з непрогралих.
- Кінець треку природним шляхом: REP=0 наступний, після останнього stop; REP=1 повтор поточного; REP=2 цикл усього списку. Ручні NEXT/PREV від REP не залежать.
Shuffle:
- Fisher-Yates по всіх треках носія (усі папки), без повторів, поки не зіграє весь список; потім перемішування заново, перший трек нового кола не дорівнює останньому зіграному.
- Вмикання не перериває трек (він вважається зіграним); вимикання: далі порядок каталогу від поточного треку.
- Для bt SHUF зберігається й звітується, але на відтворення не впливає; NEXT/PREV та PLAY/PAUSE для bt передаються як AVRCP passthrough.
Помилки відтворення: read_fail/decode_fail -> ERR і автоматичний пропуск до наступного треку, після 3 поспіль -> stop.
Резюме: для sd і usb окремо в NVS зберігати шлях треку й позицію (раз на 10 с під час play, а також при pause/stop/зміні джерела). При відсутньому файлі починати з першого треку.
Теги: ID3v2 (Latin1/UTF-16/UTF-8) і кирилиця в cp1251, усе віддається в UTF-8.
Аудіо: WROOM самостійно мʼютить свій PCM5102 (XSMT) за будь-якого state != play та при src=off, мʼют перед зупинкою без клацань. Гучністю, тембром і вибором входу керує тільки S3 (TDA7318). Різні частоти MP3 обробляє WROOM.

7. ВЕРСІЇ
Будь-яка зміна контракту = нова proto_ver і одночасне оновлення обох сторін.
=== КІНЕЦЬ КОНТРАКТУ ===
```
